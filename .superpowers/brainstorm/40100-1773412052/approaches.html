Implementation Approaches

Three ways to architect the Flow editor system

A ★

Overlay mode — canvas mounts over home3

When Tools → Flow is activated, a full-screen overlay component (canvas-01.svelte) slides over home3's content area. The nav-rail collapses to icon-only. The overlay has its own internal layout: a collapsible left palette panel, the @xyflow/svelte canvas in the center, and a right properties panel that slides in when a node is selected. A top toolbar (undo/redo, zoom, run, save) floats above the canvas. A flow picker modal/sheet opens on load if no default flow is set.

Pros

  • Stays within home3 route — auth/layout inheritance works automatically
  • canvas-01.svelte is a self-contained component — easy to reuse or move later
  • No extra routes to register
  • Palette can be dragged out as floating panel (as required)

Cons

  • home3 page component carries canvas state when overlay is open
  • Overlay z-index management needed
B

Dedicated route — /home3/flow and /home3/flow/[id]

Tools → Flow navigates to a new SvelteKit sub-route /home3/flow (flow list/manager) and /home3/flow/[id] (canvas editor). The canvas editor is its own page with a custom layout (no home3 shell). Uses SvelteKit's layout inheritance to keep auth but replaces the visual shell entirely for the editor page.

Pros

  • Shareable URLs per flow
  • Clean browser history (back button works)
  • Simpler state — page loads exactly what it needs

Cons

  • More routes and layout files
  • Full page navigation on every flow switch
  • canvas-01.svelte spec says it lives in shared-ui, not a route
C

Split view — flow manager in home3 shelf, canvas in content panel

Tools → Flow shows the flow list in home3's right shelf (replacing the context shelf). The main content area becomes the canvas. Clicking a flow in the shelf loads it. The node palette docks into the left portion of the content area or floats. Properties appear in an inline side panel on the canvas.

Pros

  • Always-visible flow list — quick switching
  • Most integrated with home3 UX

Cons

  • Canvas space is limited by shelf width
  • Palette + properties + shelf = very crowded
  • Conflicts with home3 shelf's existing use

Recommendation: A

Option A keeps canvas-01.svelte exactly where the spec says it belongs, gives maximum canvas space, and avoids routing complexity. The flow picker, palette, and properties panel all live inside the component. The overlay approach is how tools like Figma and Linear handle "focus mode" — it feels natural.
