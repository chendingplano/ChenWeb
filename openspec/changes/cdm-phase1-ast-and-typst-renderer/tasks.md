## 10. DR5d follow-up: Typst-generated TOC and figure/table/formula lists (2026/07/26)

CDM Editor spec review (ADR 2026072602 DR5d) found that Phase 1's renderer did
not satisfy the two prerequisites for Typst's own `#outline(...)` to produce a
usable TOC and lists of figures/tables/formulas. This group implements them.

- [x] 10.1 Wrapped `table` blocks in `#figure(...)` (`typst.go` `renderTable`), carrying `Block.Caption` as the figure caption when present and omitting it otherwise — verified a captionless table still numbers and lists (Typst's own default `figure` numbering, no set rule needed). Widened `Block.Caption`'s doc comment (`model/types.go`) from image-only to image-and-table; no validator change was needed since `validate.go` already validates `Caption` unconditionally regardless of block type.
- [x] 10.2 **Found and fixed a pre-existing Phase 1 bug while implementing this**, unrelated to but blocking DR5d: every block is prefixed with `#mark(id, "start")` on the same source line as its own content (`renderBlocks`), and Typst's `= ...` heading sugar only parses as a heading when it is the first token on its line. Every heading in every already-shipped CDM document was therefore rendering as literal `= Heading Text` — visually broken, and invisible to `query(heading)` (zero matches), which means numbering and outline participation were silently broken for every heading. Neither existing test caught it: `TestRenderDocument_HeadingLevel` asserted only the raw source string, and `TestGoldenFilesCompileWithTypst` asserted only that compilation succeeds — a literal `=== Sub` string satisfies both. Confirmed via direct `typst compile`/`typst query` against the previously-committed golden file before touching any code. Fixed by rendering headings via the `#heading(level: N)[...]` function form (`typst.go` `renderBlock` "heading" case), which is immune to line position; re-verified against the real compiler that this registers as a real, numbered, outline-findable heading even preceded by the mark() call.
- [x] 10.3 Added `numberingTypst` (`anchors.go`) — `#set heading(numbering: "1.1")` and `#show math.equation.where(block: true): set math.equation(numbering: "(1)")` — emitted directly in `RenderDocument`, not in `theme.typ`. **A second thing verified, not assumed**: a `#set` rule executed inside an imported module has no effect on the importing document at all, even wrapped in a called function — confirmed with a minimal repro (`styles.typ` containing the set rule, imported via `#import "styles.typ": *`, produced `numbering: null` on query either way). `#set` only affects the remainder of the scope it is textually written in, and `#import` carries bindings, not styling context. This is why `pageSetupTypst` was already a renderer constant rather than a theme setting, and why the numbering rules had to join it there instead of living in `theme.typ` as first planned.
- [x] 10.4 Added `outlinesTypst` (`anchors.go`), emitted in `RenderDocument` immediately after the title: `#outline(title: [Contents])` plus lists targeting `figure.where(kind: image)`, `figure.where(kind: table)`, and `math.equation.where(block: true)`. The document title is emitted via `#heading(numbering: none, outlined: false)[...]` instead of `= ...` sugar, so it is excluded from both content-heading numbering and the Contents outline.
