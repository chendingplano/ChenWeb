## 6. Manual verification

- [x] 6.1 **Run 2026-08-09, on the live `miner` dev DB via the Review External Resources page.** The operator re-downloaded and approved `qudt`; content was byte-identical to the already-registered 3.5.0 release, so `ApproveResource` took the idempotent-replay branch straight into the governed-term write. Post-run audit (fresh read of the real downloaded `qudt-all.ttl` through the production parser, cross-checked against `kb.ontology_terms`) found the write was **only 2/3 correct**: `quantity_kind` (1125 = 1223 raw − 98 deprecated) and `unit` (2843 = 2928 raw − 85 deprecated) landed exactly as designed, but `dimension` landed **zero** rows — a real bug, not a data gap (see below). After the bug fix, a second write (reusing the same replay path, since the keyword-lexicon side was already registered) brought `kb.ontology_terms` to the full **4213** rows across all three kinds (1125/2843/**245**), `kb.ontology_active_releases` pointing at `quantity` release `1.0.0`. Confirmed via SQL against `miner`, not synthetic fixtures. (The originally-cited "~4151" figure was always speculative per §15.2/Appendix B.2 and is superseded by this verified 4213.)
  - **Bug found and fixed:** `qudtDimensionClass` in `server/api/ontology/terminology/qudt.go` was hardcoded to `http://qudt.org/schema/qudt/DimensionVector`, which does not exist in QUDT's real vocabulary (confirmed against the downloaded file's own `@prefix qudt:` namespace and its `a qudt:QuantityKindDimensionVector, ...` triples) — the real class is `http://qudt.org/schema/qudt/QuantityKindDimensionVector`. Because `ParseQUDTGraph`'s Pass 1 only collects subjects whose `rdf:type` exactly matches the constant, all 247 real dimension-vector individuals were silently invisible to the parser (no error — `ParseQUDTGraph` only fails closed when *zero* subjects of *any* supported class are found, and `quantity_kind`/`unit` still populated). Fixed by correcting the one constant; existing tests reference it symbolically and were unaffected. Verified against the real file: 247 raw `QuantityKindDimensionVector` resources − 2 deprecated = 245 classified `dimension` terms, matching the post-fix live count exactly.
  - **Incident during verification (self-inflicted, corrected same session):** the integration suite (`qudt_ontology_test.go`) was accidentally run with `TEST_DATABASE_URL` pointed at the live `miner` database instead of the dedicated `chenweb_test` database. Its setup/cleanup unconditionally deletes `module_id='quantity'` rows across `kb.ontology_terms`/`kb.ontology_module_releases`/`kb.ontology_active_releases`/`kb.ontology_mappings`/`kb.ontology_modules` "in case a prior failed run left rows behind," which wiped the real quantity-module data just written. `core` and every `kb.keyword_*` table were unaffected (the `core`-seeding helper no-ops when `core` already exists; the deletes only ever target `quantity`). Recovered by re-running the exact same `writeQUDTTermsReplay`/`releaseQUDTIfPending` production functions (via a temporary, since-deleted wrapper) against `miner` — which also delivered the post-fix backfill in the same pass, landing at the 4213-row state described above. Lesson for future runs of this suite: always set `TEST_DATABASE_URL` to `chenweb_test`, never `miner`.
